## Jerarquía de Herencia

El backend usa **JPA Inheritance JOINED** con `Usuario` como entidad base. Cada tipo de usuario tiene su propia tabla con campos específicos.

```
Usuario (base, @Inheritance(JOINED))
  ├── Ciudadano     → dni, nombreCompleto, telefono, direccion
  ├── Funcionario   → nombreCompleto, cargo, area, telefono, entidad
  ├── MiembroTTAIP  → nombreCompleto, cargo, sala, especialidad
  └── Administrador → nombreCompleto, rol, permisos
```

    ```java
    @Entity
    @Table(name = "usuarios")
    @Inheritance(strategy = InheritanceType.JOINED)
    public class Usuario {
        @Id
        @GeneratedValue(strategy = GenerationType.IDENTITY)
        private Long idUsuario;

        @Column(unique = true, nullable = false)
        private String email;

        @Enumerated(EnumType.STRING)
        private TipoUsuario tipoUsuario;

        @PrePersist
        protected void onCreate() {
            this.fechaRegistro = LocalDateTime.now();
            this.activo = true;
        }
    }
    ```

## Entidades de Dominio

### Solicitud

Representa una Solicitud de Acceso a la Información Pública (SAIP).

| Campo | Tipo | Descripción |
|-------|------|-------------|
| `id` | `Long` | PK |
| `expediente` | `String` | Formato `SAIP-AAAA-NNNNN`, unique |
| `asunto` | `String` | Tema de la solicitud |
| `descripcion` | `String` | Detalle de la información solicitada |
| `ciudadano` | `Ciudadano` | ManyToOne |
| `entidad` | `Entidad` | ManyToOne |
| `estado` | `EstadoSolicitud` | Enum (7 valores) |
| `prioridad` | `Prioridad` | Enum (5 niveles) |
| `fechaPresentacion` | `LocalDateTime` | Auto-set |
| `fechaLimite` | `LocalDate` | Calculada: +10 días hábiles |
| `diasRestantes` | `Integer` | `@Transient`, calculado |
| `semaforoEstado` | `String` | `@Transient`: VERDE/AMBAR/ROJO/NEGRO |
| `tipoInformacion` | `String` | — |
| `formatoDigital` | `Boolean` | — |
| `formatoFisico` | `Boolean` | — |
| `copiaSimple` | `Boolean` | — |
| `copiaCertificada` | `Boolean` | — |
| `respuesta` | `Respuesta` | OneToOne, mappedBy solicitud |
| `apelacion` | `Apelacion` | OneToOne, mappedBy solicitud |
| `documentos` | `List<Documento>` | OneToMany |

:::tip
La `fechaLimite` se calcula automáticamente en `@PrePersist` usando `DiasHabilesUtil.sumarDiasHabiles()`, que excluye sábados, domingos y 14 feriados nacionales peruanos.
:::

## Diagrama de Relaciones

```
Ciudadano ──1:N──> Solicitud ──1:1──> Respuesta ──N:1──> Funcionario
     │                  │                   │
     │                  1:1                 │
     │                  │                   │
     └──1:N──> Apelacion ──1:N──> Resolucion ──N:1──> MiembroTTAIP
                    │
                    │
          Funcionario ──N:1──> Entidad ──1:N──> Solicitud

Documento (polimórfico) ──N:1──> Solicitud | Respuesta | Apelacion | Resolucion
```

## Repositorios JPA

Todos los repositorios extienden `JpaRepository` con queries JPQL personalizadas:

```java
public interface SolicitudRepository
        extends JpaRepository<Solicitud, Long> {
    Optional<Solicitud> findByExpediente(String expediente);

    @Query("SELECT s FROM Solicitud s " +
           "LEFT JOIN FETCH s.documentos " +
           "LEFT JOIN FETCH s.respuesta " +
           "WHERE s.id = :id")
    Optional<Solicitud> findByIdWithDetails(@Param("id") Long id);

    List<Solicitud> findByEstado(EstadoSolicitud estado);

    @Query("SELECT s FROM Solicitud s " +
           "WHERE s.estado NOT IN ('RESPONDIDA','DENEGADA','CONCLUIDA','VENCIDA') " +
           "AND s.fechaLimite < CURRENT_DATE")
    List<Solicitud> findVencidas();
}
```

:::note
Se usa `JOIN FETCH` para prevenir el problema N+1 en consultas que necesitan cargar relaciones.
:::
