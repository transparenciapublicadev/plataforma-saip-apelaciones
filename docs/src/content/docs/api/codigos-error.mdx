## Formato Estándar de Error

Todas las respuestas de error siguen el formato `ApiError`:

```json
{
  "status": 400,
  "error": "Bad Request",
  "message": "asunto: no debe estar vacío, entidadId: no debe ser nulo",
  "timestamp": "2025-01-15T10:30:00",
  "path": "/api/solicitudes"
}
```

| Campo | Tipo | Descripción |
|-------|------|-------------|
| `status` | `int` | Código HTTP |
| `error` | `String` | Descripción corta del error HTTP |
| `message` | `String` | Detalle legible del error |
| `timestamp` | `String` | Fecha y hora del error |
| `path` | `String` | Ruta del endpoint que generó el error |

## GlobalExceptionHandler

El manejo centralizado de excepciones se realiza en `GlobalExceptionHandler`:

```java
@ControllerAdvice
public class GlobalExceptionHandler {

    // Validación de campos (Jakarta Bean Validation)
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ApiError> handleValidation(
            MethodArgumentNotValidException ex) {
        String message = ex.getBindingResult().getFieldErrors().stream()
            .map(e -> e.getField() + ": " + e.getDefaultMessage())
            .collect(Collectors.joining(", "));
        return ResponseEntity.badRequest()
            .body(ApiError.validation(message));
    }

    // Recurso no encontrado
    @ExceptionHandler(RecursoNoEncontradoException.class)
    public ResponseEntity<ApiError> handleNotFound(
            RecursoNoEncontradoException ex) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
            .body(ApiError.notFound(ex.getMessage()));
    }

    // Regla de negocio violada
    @ExceptionHandler(ReglaNegocioException.class)
    public ResponseEntity<ApiError> handleBusinessRule(
            ReglaNegocioException ex) {
        return ResponseEntity.status(HttpStatus.UNPROCESSABLE_ENTITY)
            .body(ApiError.businessRule(ex.getMessage()));
    }

    // Error genérico
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ApiError> handleGeneric(Exception ex) {
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
            .body(ApiError.internal("Error interno del servidor"));
    }
}
```

## Excepciones Custom

| Excepción | Código HTTP | Uso |
|-----------|-------------|-----|
| `RecursoNoEncontradoException` | `404` | Solicitud, apelación o usuario no encontrado |
| `ReglaNegocioException` | `422` | Violación de regla de negocio (plazo vencido, estado inválido) |
| `AccesoNoAutorizadoException` | `403` | Intento de acceder a recurso de otro usuario |
| `EstadoInvalidoException` | `409` | Transición de estado no permitida |

## Manejo en Clientes

| Módulo | Estrategia |
|--------|-----------|
| **Frontend** | `catchError` en pipes RxJS → muestra mensaje al usuario con señales de error |
| **Mobile** | `try/catch` en `viewModelScope.launch` → actualiza `uiState.error` |
| **Backend** | `GlobalExceptionHandler` centraliza TODAS las excepciones |
