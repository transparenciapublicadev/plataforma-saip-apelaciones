## Formato Estándar de Error

Todas las respuestas de error siguen RFC 9457 / Problem Details con `Content-Type: application/problem+json`:

```json
{
  "type": "urn:saip:problem:validation-failed",
  "title": "Validation failed",
  "status": 400,
  "detail": "asunto: no debe estar vacío, entidadId: no debe ser nulo",
  "instance": "/api/solicitudes",
  "timestamp": "2025-01-15T10:30:00",
  "success": false,
  "mensaje": "asunto: no debe estar vacío, entidadId: no debe ser nulo"
}
```

| Campo | Tipo | Descripción |
|-------|------|-------------|
| `type` | `URI` | Identificador estable del tipo de problema |
| `title` | `String` | Descripción corta y estable del problema |
| `status` | `int` | Código HTTP |
| `detail` | `String` | Detalle legible del error concreto |
| `instance` | `URI` | Ruta del endpoint que generó el error |
| `timestamp` | `String` | Fecha y hora del error |
| `success` | `boolean` | Extensión de compatibilidad; siempre `false` |
| `mensaje` | `String` | Extensión de compatibilidad equivalente a `detail` |

## GlobalExceptionHandler

El manejo centralizado de excepciones se realiza en `GlobalExceptionHandler`:

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // Validación de campos (Jakarta Bean Validation)
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ProblemDetail> manejarValidacion(
            MethodArgumentNotValidException ex,
            HttpServletRequest request) {
        ProblemDetail problem = ApiProblemDetails.create(
            HttpStatus.BAD_REQUEST,
            "Validation failed",
            "...detalle de campos inválidos...",
            request.getRequestURI());
        return ResponseEntity.badRequest().body(problem);
    }

    // Recurso no encontrado
    @ExceptionHandler(RecursoNoEncontradoException.class)
    public ResponseEntity<ProblemDetail> manejarNoEncontrado(
            RecursoNoEncontradoException ex,
            HttpServletRequest request) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
            .body(ApiProblemDetails.create(
                HttpStatus.NOT_FOUND,
                "Resource not found",
                ex.getMessage(),
                request.getRequestURI()));
    }
}
```

## Clasificación Centralizada

| Excepción o condición | Código HTTP | Uso |
|-----------------------|-------------|-----|
| `RecursoNoEncontradoException` | `404` | Solicitud, apelación o usuario no encontrado |
| `IllegalArgumentException` por duplicidad | `409` | Recurso existente o duplicado activo |
| `IllegalArgumentException` por plazo, estado o transición | `422` | Regla de negocio incumplida |
| `IllegalArgumentException` restante | `400` | Input inválido |
| `AuthenticationException` | `401` | Token ausente, inválido o expirado |
| `AccessDeniedException` | `403` | Rol insuficiente |
| `Exception` no controlada | `500` | Error real de backend registrado en logs |

## Manejo en Clientes

| Módulo | Estrategia |
|--------|-----------|
| **Frontend** | `catchError` en pipes RxJS → muestra mensaje al usuario con señales de error |
| **Mobile** | `try/catch` en `viewModelScope.launch` → actualiza `uiState.error` |
| **Backend** | `GlobalExceptionHandler` centraliza TODAS las excepciones |
