El navegador de producción usa `apiUrl: '/api'`. Solo el proceso SSR sustituye

## Build de Producción

<Steps>
1. **Instalar** dependencias desde la raíz del monorepo
   ```bash
   pnpm --dir frontend install --frozen-lockfile
   ```
2. **Compilar** para producción
   ```bash
   pnpm --dir frontend run build
   ```
   Esto genera `frontend/dist/saip-frontend/` con el navegador y el servidor SSR.
3. **Ejecutar** SSR
   ```bash
   node frontend/dist/saip-frontend/server/server.mjs
   ```
</Steps>

## Variables de Entorno

| Variable | Descripción | Default |
|----------|-------------|---------|
| `PORT` | Puerto del servidor SSR dentro del contenedor | `4000` |
| `API_INTERNAL_ORIGIN` | Origen del backend visto solo por el SSR | `http://backend:8080` en Compose |
| `PUBLIC_ORIGIN` | Origen HTTPS público. El SSR rechaza un Host distinto | Obligatorio en la imagen publicada |

Desarrollo local sigue en `environment.ts` con `http://localhost:8080/api`.
Producción está en `environment.production.ts` y usa `/api`.

## Optimizaciones Incluidas

| Optimización | Detalle |
|-------------|---------|
| Tree-shaking | Eliminación de código no usado |
| Lazy loading | Rutas cargadas bajo demanda con `loadComponent` |
| SSR | Server-Side Rendering con Express para SEO y rendimiento |
| OnPush | Detección de cambios optimizada en todos los componentes |
| AOT | Compilación Ahead-of-Time habilitada por defecto |

## Consideraciones

:::caution[SSR y localStorage]
El interceptor de autenticación verifica `isPlatformBrowser` antes de acceder a `localStorage`. Esto es necesario porque durante el SSR no existe el objeto `window`.
:::

:::note[CORS]
El backend debe incluir el dominio de producción del frontend en la configuración CORS permitida.
:::
