## Build de Release

<Steps>
1. **Configurar firma**
   ```kotlin
   android {
       signingConfigs {
           create("release") {
               storeFile = file(System.getenv("KEYSTORE_PATH"))
               storePassword = System.getenv("KEYSTORE_PASSWORD")
               keyAlias = System.getenv("KEY_ALIAS")
               keyPassword = System.getenv("KEY_PASSWORD")
           }
       }
   }
   ```
2. **Compilar bundles o APKs por flavor**
   ```powershell
   cd mobile
   .\gradlew.bat bundleCiudadanoRelease
   .\gradlew.bat assembleFuncionarioRelease
   .\gradlew.bat assembleTtaipRelease
   ```
3. **Validar antes de distribuir**
   ```powershell
   .\gradlew.bat :app:compileCiudadanoDebugKotlin
   .\gradlew.bat :app:compileFuncionarioDebugKotlin
   .\gradlew.bat :app:compileTtaipDebugKotlin
   .\gradlew.bat test
   ```
</Steps>

## Variables y Configuración

| Variable | Descripción |
| --- | --- |
| `KEYSTORE_PATH` | Ruta del archivo `.jks`. |
| `KEYSTORE_PASSWORD` | Contraseña del keystore. |
| `KEY_ALIAS` | Alias de la clave. |
| `KEY_PASSWORD` | Contraseña de la clave. |
| `REST_BASE_URL` | URL base del backend Spring Boot. |

Para desarrollo local:

| Entorno | `REST_BASE_URL` |
| --- | --- |
| Emulador Android | `http://10.0.2.2:8080/` |
| Dispositivo con `adb reverse tcp:8080 tcp:8080` | `http://127.0.0.1:8080/` |
| Dispositivo físico en LAN | URL LAN del backend |

Sobrescribir el valor en `mobile/local.properties`. Ese archivo no se versiona.

:::danger[Secrets]
No versionar keystores, passwords, tokens, `google-services.json` de producción ni archivos con credenciales.
:::

## Firebase Cloud Messaging

El archivo `google-services.json` se usa únicamente para FCM. La app no debe usar Firebase Auth ni Firestore.

La API key Android preexistente debe restringirse desde Firebase Console al package name y certificado SHA correspondiente a cada distribución. Esta medida se configura en Firebase/Google Cloud Console; no requiere editar ni mover `google-services.json` dentro de este hardening.

Responsabilidades de FCM:

- Obtener token push del dispositivo.
- Suscribir topics por rol si aplica.
- Recibir mensajes en `MiSaipMessagingService`.
- Registrar o renovar el token contra `POST /api/notificaciones/push/tokens` después de login, splash con sesión válida u `onNewToken`.
- Revocar el dispositivo actual contra `POST /api/notificaciones/push/tokens/revocar-actual` antes de limpiar el JWT durante logout.

El token se trata como dato opaco: la app no lo escribe en logs ni Firestore. Si backend no está disponible, el alta o revocación no bloquea login/logout; se reintenta en la próxima sesión o renovación. El envío real desde backend permanece pendiente de integrar Firebase Admin con secretos externos.

## R8 / ProGuard

Incluir reglas para librerías que usan reflexión o serialización:

```text
# Retrofit / OkHttp
-keepattributes Signature
-keepattributes *Annotation*
-keep class retrofit2.** { *; }
-keep class okhttp3.** { *; }

# DTOs de red
-keep class com.gestion.misaip.core.network.dto.** { *; }

# SQLDelight
-keep class com.gestion.misaip.core.database.** { *; }

# Firebase Messaging
-keep class com.google.firebase.messaging.** { *; }
```

## Checklist de Release

- Compilar los tres flavors.
- Confirmar que cada APK rechaza sesiones de otros roles.
- Probar login contra backend real o staging.
- Probar consulta de SAIP y apelaciones según rol.
- Probar recepción de push FCM.
- Verificar que no existan logs sensibles.
- Confirmar que `mobile/openapi.json` coincide con el contrato publicado.
- Confirmar que la app ciudadano es la única destinada a Play Store pública.
