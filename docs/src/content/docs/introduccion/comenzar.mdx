## Orden Recomendado

<Steps>
1. Levantar MySQL y preparar la base de datos `saip_db`.
2. Ejecutar backend y validar `/v3/api-docs`.
3. Sincronizar contrato OpenAPI si hubo cambios de API.
4. Ejecutar frontend Angular.
5. Ejecutar mobile con el flavor requerido.
6. Ejecutar docs Starlight y validar que la documentación compile.
</Steps>

## Backend

```powershell
cd backend
.\mvnw.cmd test
.\mvnw.cmd spring-boot:run
```

Variables habituales:

| Variable | Uso |
| --- | --- |
| `DB_URL` | JDBC de MySQL. |
| `DB_USERNAME` | Usuario de base de datos. |
| `DB_PASSWORD` | Password de base de datos. |
| `JWT_SECRET` | Secreto HMAC para firmar JWT. |
| `APP_CORS_ALLOWED_ORIGINS` | Orígenes permitidos para frontend. |

Validaciones rápidas:

```powershell
curl http://localhost:8080/v3/api-docs
curl http://localhost:8080/swagger-ui.html
```

## Frontend

```powershell
cd frontend
npm install
npm test
npm run build
npm start
```

Sincronizar tipos desde backend activo:

```powershell
cd frontend
npm run generate:api:live
```

La aplicación web corre por defecto en:

```text
http://localhost:4200
```

## Mobile

El módulo mobile genera tres APKs independientes por rol.

```powershell
cd mobile
.\gradlew.bat :app:compileCiudadanoDebugKotlin
.\gradlew.bat :app:compileFuncionarioDebugKotlin
.\gradlew.bat :app:compileTtaipDebugKotlin
```

Build por flavor:

```powershell
.\gradlew.bat assembleCiudadanoDebug
.\gradlew.bat assembleFuncionarioDebug
.\gradlew.bat assembleTtaipDebug
```

Configurar backend para emulador o dispositivo:

```properties
# mobile/gradle.properties o local.properties
REST_BASE_URL=http://10.0.2.2:8080/
```

:::caution[Firebase]
Firebase ya no es backend de autenticación ni de datos. El único servicio conservado es **Firebase Cloud Messaging** para recibir push notifications.
:::

## Documentación Starlight

```powershell
cd docs
npm ci
npm run build
npm start
```

La documentación local corre por defecto en:

```text
http://localhost:4321
```

## Postman

Importar:

- `postman/SAIP-API-Collection-Complete.json`
- `postman/SAIP-API-Environment-Complete.json`

Flujo recomendado:

<Steps>
1. Seleccionar environment `SAIP Backend - Environment`.
2. Ejecutar los logins para poblar tokens por rol.
3. Ejecutar carpetas por dominio: SAIP, respuestas, apelaciones, TTAIP, reportes.
4. Revisar ejemplos de éxito y error en la pestaña **Examples** de cada request.
</Steps>
